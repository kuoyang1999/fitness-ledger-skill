# 专项记录与计划执行

**简体中文** · [English](event-records.en.md)

按本次涉及的专项读取相应段落。优先沿用用户现有字段、单位、器械约定和确认记录。

## 私有配置

用户可在自己指定的私有配置中保存力量 A/B、训练场地与器械档位、每周跑量、赛事目标、饮食配方、测量频率及单位。读取任务所需部分，并记录配置的版本或生效依据。公开 Skill 只提供通用方法。

缺少某项配置时，先查现有记录。足以完成事实记录的内容直接处理。具体训练量、目标配速和营养目标按用户选择配置，建议获得采纳后再进入有效计划。

## 共同记录口径

- 一次真实事件使用一个父记录。逐组、分段、线路尝试等从属于该父事件，事件次数、时长、距离和消耗从父记录统计。
- 分别保存发生时间、时区、旧归档日期、录入时间，以及账本启用时的作息归属。归属有依据而钟点未知时，可保留归属依据并让钟点留空。
- 保留用户原话、原单位、设备或应用来源及后续更正。派生数值注明计算依据。缺失与来源冲突保留待核状态。
- 同一事件经多个应用同步时，核对原始事件标识、UTC 起止、项目和内容。保留一份计数事实及镜像来源。标识缺失时使用这些可核验特征查重。

## 力量逐组

每行记录已报告的动作、组类、原始负重与口径、实际次数。RIR、RPE 和当组反馈有报告时保留。已知内容先记入，未报告项留空。

- 组类区分热身、校准、工作、额外工作、测试及中断。正式组总数包含实际完成的额外工作组，并说明与原安排的差异。
- 负重注明杠铃总重、史密斯每侧片重、每只哑铃重量、单手总外负重或器械显示值。杆阻力、滑轮倍率未知时保留未知。跨器械比较同时核对设置。
- 单侧动作保留每侧次数及左右反馈。双侧完成可按用户既有组数口径记一组，另行说明实际计数方式。
- RIR 范围和加号按原报告保存。通用热身、拉伸和症状变化分别记录，计划项目按实际报告完成情况填写。
- 逐组行使用父事件与稳定行号定位。更正同一行的重量、次数或反馈时保留修订依据。父摘要同步当前组数与收训状态。

## 跑步与攀岩

| 专项 | 记录和复核要点 |
| --- | --- |
| 跑步总量 | 距离、运动计时、起止经过时间分别保存。保留设备原始秒数。界面只能存分钟时在正文保存精确起止。平均配速注明所采用的距离与时长口径。 |
| 跑步明细 | 分段或间歇记录距离、计时、目标、实际表现和恢复段。显示取整造成的合计差异保留说明。整场平均配速与快速组配速分别分析。 |
| 跑步来源 | 截图与原始 Workout 的距离、热量或心率差异保留双方来源，说明主字段取值。心率注明整场、睡窗或指定时窗聚合，步频注明是否包含走休。路线、爬升、跑鞋和跑姿数据按实际证据填写。 |
| 攀岩 | 区分抱石、难度攀登等类型，注明场地、难度体系、线路或问题、尝试次数、完成方式和主观反馈。设备短段与人工整场记录先核对覆盖是否相同，再决定合并或分别保留。 |

根据用户指认、课程标识或训练日期、项目与内容核对计划。仅距离相近时标为候选，确认对应关系后再关联。课程逐段达标情况依据实际分段或用户报告判断。跨午夜训练保留一个父事件。采用作息日时按实际开始归属，后续恢复反馈注明报告时间。

## 饮食配方与实际摄入

- 配方或产品档案保存每份原料、用量、营养来源及版本。摄入记录保存实际采用的版本、份数、增减配料和生熟重口径。产品标签与配方档案本身属于参考资料。
- 用户修改默认配方后，记录生效依据。历史摄入沿用当时实际配方。若属于历史事实更正，更新相应原记录并保留更正理由。
- 计划吃、已经吃、部分吃和取消分别记录。照片估份、多人分食和剩余量明确写出假设。无法确定份量时保留估算范围或待核项。
- 补剂剂量、含咖啡因产品和液体套餐中的成分按实际份数计入。同一成分已在套餐中时，核对是否另有一份真实摄入。
- 营养合计说明覆盖、估算和缺值。对已知分项可报告工作小计。未获得的宏量或热量保持空白。

## 体测与 DEXA

- 一次测量会话为一个父事件。保存各次原始读数、单位、测点和代表值算法。只知道代表值时标明来源形式。
- 体重、围度、皮褶按用户协议使用单位和频率。同日多次均值与跨日趋势作为分析，引用原会话。
- DEXA 单独保存体脂率、脂肪量、瘦体组织、骨矿物质及区域指标等实际报告项目。记录设备、测量时刻、进食、水合、排尿和近期运动条件。
- 皮褶估算与 DEXA 使用各自方法和趋势。测量协议变更时标注新基线条件。解读瘦体组织变化时同时考虑水分与测量误差。

## 后补与跨专项复核

后补事实写回对应原事件，再检查直接受影响的当前字段和摘要。例如，跑中补胶已在饮食模块确认后，训练页引用该原摄入记录，更新仍写“补给未知”的当前描述。营养由原摄入记录汇总，训练页保存关联与解释。

周期边界、事件起止或统计开关修订后，重新核对受影响父事件、从属明细和汇总。最新归属依据采用修订后的边界，旧依据标为历史。保留原始证据和有日期的阶段快照，当前入口显示最新已核实状态。

## 计划版本与执行进度

新项目编排时，先结合最近已完成训练的量与强度、目标日期、每周可用时段、可用器械及睡眠、疲劳和不适反馈，拟出一周可执行草案。列出每次训练的目的、预计时长、组数或跑量、强度范围及恢复安排，兼顾不同专项的累积负荷。缺少训练历史时标明起点假设，采用可调整的初始量。按实际完成和恢复反馈修订。草案保存依据及待确认项，用户采纳后再更新有效版本。

- 保存草案、已确认、已替代、已结束等状态及确认依据、生效范围和前一版本。用户只采纳部分建议时，明确该部分范围。
- 计划日期、预计组数、目标距离和配速保留原意。实际执行通过原训练事件关联，取消、部分完成、额外完成和改期分别说明。
- 已确认排程后续有实际执行时，更新当前进度摘要或增加注明核对时点的执行段，并链接原事件。原排程快照标明其时点。
- 对同日距离吻合但缺分段的跑步，可写“已记录对应跑步，课程分段待核”。对一次力量临时换动作或减组，记录当次变化及原因，长期模板依据用户采纳另行修订。
- 汇报进度时同时核对最新有效版本与原事件。仅有建议的目标、饮食量或恢复安排继续保留其建议状态。

# 作息日与每日运动双汇总

**简体中文** · [English](sleep-day.en.md)

处理凌晨记录、睡眠导入、跨时区事件或每日汇总时读本页。先读取项目现有规范和字段定义。本页给出通用方法，个人习惯、实际时区和已采纳的例外保存在用户自己的项目中。

## 以主睡眠的最终醒来划分周期

一个作息周期采用左闭右开区间：**本次主睡眠最终醒来 ≤ 事件发生时刻 < 下一次主睡眠最终醒来**。周期用稳定的记录 ID 识别。“作息日”是从开始醒来时的当地日期派生的显示标签，日期本身不保证唯一。

- 凌晨仍未入睡，餐食和训练继续属于当前周期。午夜不自动切日。
- 午睡、夜间短醒和醒后继续同一段主睡眠，不开新周期。分段主睡眠可含清醒间隔。间隔不能填成睡眠。
- 用“清醒 → 候选主睡眠待确认 → 最终醒来后开新周期”的状态推进。入睡可作为暂停活动的证据。不能仅凭入睡推断下一周期已开始。
- 判断主睡眠要结合本人说明、睡眠连续性、后续活动和近期习惯。时长或固定钟点只能辅助判断，不能单独决定“短睡就是午睡”或“过某点必定切日”。
- 本人明确说“还没睡”“这只是午睡”“已经起床开始今天”，应覆盖纯习惯估计。与设备记录不一致时保留两种证据，解释采用哪个边界。
- 有证据确认整夜未睡，周期可以超过 24 小时。只有睡眠资料缺失时，不能推导出连续多日清醒，也不能让所有后续事件无限挂在旧周期。

**开日睡眠只计一次。** 唤醒当前周期的主睡眠，作为当前周期的开日恢复数据，尽管其睡眠区间在时间上位于当前周期开始之前。前一周期只使用这次最终醒来作为结束边界，不再加总同一段主睡眠。日间小睡归发生时的活动周期，单列为小睡，不替代或重复计算开日主睡眠。睡眠片段与所属周期应有唯一、可追溯的关联。

## 睡眠证据与 Apple Health

分别判断“何时醒来”“睡了多久”“事件归哪个周期”，不要用一个证据替代所有答案。边界通常优先采用本人明确的最终醒来或未睡说明，再结合有时间和来源的睡眠记录、同时段活动，最后才使用近期个体化估计。睡眠时长依据实际睡眠片段。本人说起床时间，不等于设备最后片段到起床之间也都在睡。

Apple Health 当前可读且本次任务允许读取时：

1. 读取 Apple Health 的 `sleepAnalysis` 睡眠样本，查询覆盖目标边界前后的窗口，记录真实查询时间、UTC 范围、来源、分页是否取尽和返回覆盖。只有本次成功读取的内容才能称“已查询”。
2. 保留原始时间、设备或应用、睡眠类别和实际返回的来源标识。没有原生 ID 时，可用来源、原始起止时刻和类别形成查重依据，不能冒充原生 ID。
3. 检查多设备、镜像应用和睡眠阶段的重叠。同一时间的通用“睡着”与细分阶段不能重复相加。清醒不计睡眠，“卧床”也不等于睡着。保留原始值与去重后的计算口径。
4. 设备最后一个睡眠片段结束仅是候选醒来边界。结合本人是否又睡、是否开始活动核实最终醒来。不要把片段之间的空白补成睡眠。
5. 查询完成不代表全部现实睡眠已同步。延迟同步时先复用已有周期和睡眠事件，再修正边界、关联及受影响摘要，避免新建重复周期。

没有连接、读取失败或窗口内没有样本，都只能说明证据不可用或未返回，不能写成“未睡”。遵守工具返回的访问限制。不要把拒绝改写成成功或通过其他路径重试同一受限来源。仍可使用已经合法取得的记录、本人说明及任务范围内的估计。

## 缺失时采用近期个体化估计

估计使用与目标时段相近、相同生活环境的近期已核验主睡眠。可从最近 14 天开始，按同一作息环境筛选实测样本。保存窗口、样本数、醒来时间的中位数或范围、适用时区及排除原因。不要把午睡或旧估计再次当成实测样本，形成自我强化。近期旅行、轮班、熬夜或习惯改变时，降低旧习惯的权重。样本少就明确置信不足，不套用统一的固定切日时刻。

先用事件本身的语义缩小归属：本人说“昨晚未睡前”“今天起床后”的证据，通常比惯常醒来钟点更直接。录入时间、图片保存时间和聊天发送时间，不自动等于发生时间。

在当前任务已经允许估算归档的范围内：

- 能合理确定周期标签、但无法确定精确边界时，可创建或复用**推定周期**。记录依据和估计窗口，精确开始、结束及实际睡眠字段保持空白，事件关联标为推定。
- 仅当证据支持具体时间、字段本身也允许估计时，才填估计边界，并明确标为估计。中位醒来钟点不能直接变成精确实测时间。
- 无法在两个周期之间可靠判断时，保留事件和原归档，标为待归属，列出缺少的证据。不要强塞进当前打开的周期。没有发生时间的旧记录尤其如此。
- 后续补到实测，按原事件及已有推定周期校正。保留原 ID、估计依据和更正记录。此次对一批记录的估计授权，不自动扩展为全历史迁移。

## 时区、旅行与夏令时

按 UTC 绝对时刻比较先后与计算经过时长，同时保留事件原始当地时间、偏移量及可知的 IANA 时区。电脑时区、查询显示时区或当前所在地，不能直接替代历史发生地。

旅行不会单独开新作息周期。跨时区周期的起止可以使用不同当地时区，标签沿用开始醒来的当地日期，稳定 ID 保持不变。同名日期或跳过日期不必强行修正。夏令时重复的当地小时需要偏移量来消歧，跳过的小时不能凭空构造。若只有当地钟点而无可靠时区，保留时间不确定性，避免制造唯一 UTC 时刻。

只有日期的旧记录不因新作息规则而整体前移或后移。预约、比赛、计划生效日等日历日期仍按其原本含义记录。

## 最少需要表达的信息

复用已有字段。以下是语义要求，不要求把每项都新建为独立属性。

| 对象 | 最少信息 |
| --- | --- |
| 周期 | 稳定 ID、派生作息日标签、起止时刻与时区（可空）、边界状态和依据、开放或已闭合状态 |
| 开日睡眠 | 唯一来源关联、实际睡眠片段或去重时长、最终醒来依据。实测、混合、估计、未知分别标明 |
| 原事件 | 原发生时间及精度、原归档标签、唯一周期关联或待归属、关联依据、来源 |
| 汇总 | 所属周期、快照类型、生成时间、数据截止时间、实际读取覆盖、完整性及需重算状态 |

周期闭合与记录完整是两个维度：边界已知仍可能缺少餐食。记录看似齐全也可能尚未确认下一次醒来。未知不填 0，部分数据不标成全天。

## 每日运动双汇总的职责

由每日双汇总维护共享周期和睡眠边界。饮食、训练、体测等专项聊天提供原事件、来源和候选归属，引用同一个周期，避免各自新建一天。当前维护者按项目既有规范协调，不擅自修改其他聊天的定时任务。

- **午间快照**：说明针对哪个周期、截至何时、实际读到哪些记录。只总结当时已记录的活动和摄入，指出尚未覆盖的部分。
- **阶段快照**：午夜到来但周期未结束时，继续当前周期并注明阶段状态。定时任务的执行钟点与作息周期边界分开管理，不因换分日口径自动改时间或频率。
- **最终快照**：下一次最终醒来已经核实，且已检查影响归属的事件后，生成该周期的最终摘要。若终点只有习惯估计，继续保存阶段快照，注明估计依据和下一项待核证据。

每份快照区分生成时间、数据截止时间和来源覆盖。边界闭合后仍缺记录，就保留“部分覆盖”。不要把未记录摄入解释成未摄入，或据此计算确定的全天缺口。只提供自然日聚合的步数、活动能量等指标保留原时间窗口。有逐时或逐样本数据时，按真实周期范围去重汇总。运动消耗和总日消耗分别标明口径。

延迟同步或补报改变边界时，保留旧快照作为历史，标记受影响摘要待重算，并更新当前有效版本及更正依据。不能让旧正文中的“待核对”继续冒充当前状态，也不能无说明地覆盖当时的记录。

## 兼容历史归档和旧汇总

保留原始发生时间、旧日期、旧每日关系、原值及来源。旧日期可能是自然日、饮食日或当时约定的归档日，应按原定义解释，不能统一改称自然日。新增周期关联时，让作息日标签只读派生。原事件只归一个周期，从属明细沿用父记录归属。

新统计从已去重、归属明确的原事件计算。不能同时累加原事件和旧每日汇总。估计、未知与完整覆盖分开呈现。“最近七个周期”与“截至某时刻的七天 UTC 窗口”也应注明区别。

迁移只声明实际处理的范围，留下原关联、新关联、更改原因与可回退映射。没有时间的历史事件可以继续保留旧归档并待核，不为凑齐趋势图编造边界。部分历史已关联，不等于全历史完成迁移。

## 完全虚构的边界示例

以下人物、日期与记录均为虚构，时区统一为 `Etc/UTC`。

| 记录 | 判断 |
| --- | --- |
| 示例甲在 2040-06-04 08:40 最终醒来 | 开启标记为 06-04 的周期 |
| 06-05 00:25 吃夜宵，并说明仍未入睡 | 夜宵归 06-04 周期，不按午夜切日 |
| 02:10 后主睡眠，06:00 短醒吃东西，06:25 又睡。设备最后睡眠片段到 09:05，本人确认 09:20 才最终醒来 | 06:00 的进食仍归 06-04 周期。09:20 才开启 06-05 周期。设备片段与本人报告都保留，09:05–09:20 不自动算睡眠 |
| 上述主睡眠的去重睡眠片段 | 只计入 06-05 周期的开日睡眠。06-04 周期用 09:20 作结束边界，不重复加总睡眠 |
| 06-05 16:00–16:25 明确为午睡 | 归 06-05 周期的小睡，不开启新周期 |

如果之后一天缺少设备样本，只能标记缺证据。若已获准估算且“起床后午餐”的语义能确定归档标签，可关联推定周期并保留空的精确边界。不能据此生成一段“实测睡眠”，也不能断言示例甲整夜未睡。

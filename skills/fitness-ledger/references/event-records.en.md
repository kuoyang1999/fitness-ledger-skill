Read the sections relevant to the current task. Prefer the user's existing fields, units, equipment conventions, and recorded confirmations.

## Private Configuration

Users can keep strength A/B routines, training locations and available equipment increments, weekly running mileage, race goals, meal recipes, measurement frequency, and units in a private configuration of their choice. Read the parts needed for the task and record the configuration version or the evidence establishing when it took effect. The public skill provides general methods.

When a configuration item is missing, check existing records first. Proceed with any facts that can already be recorded. Set specific training volumes, target paces, and nutrition goals according to the user's choices, and add recommendations to the active plan once the user adopts them.

## Shared Recording Conventions

- Use one parent record for each actual event. Sets, splits, route attempts, and similar details belong to that parent. Count events, duration, distance, and energy expenditure from parent records.
- Keep occurrence time, time zone, the previous filing date, entry time, and sleep day assignment separate, with sleep day assignment included when the ledger uses it. When an assignment has supporting evidence but the clock time is unknown, retain the assignment evidence and leave the time blank.
- Preserve the user's wording, original units, device or app sources, and subsequent corrections. State the calculation basis for derived values. Keep missing information and source conflicts marked for verification.
- When multiple apps sync the same event, compare original event identifiers, UTC start and end times, activity type, and content. Keep one counted event and retain its mirrored sources. If identifiers are missing, use these verifiable attributes to check for duplicates.

## Strength Sets

For each row, record the reported exercise, set type, original load and its convention, and actual repetitions. Retain RIR, RPE, and set feedback when reported. Record known details first and leave unreported fields blank.

- Distinguish warm-up, calibration, work, additional work, test, and interrupted sets. Include completed additional work sets in the work-set total, and explain differences from the original arrangement.
- Specify whether a load is total barbell weight, plates per side on a Smith machine, weight per dumbbell, total external load held in one hand, or the machine's displayed setting. Leave unknown bar resistance and pulley ratios unknown. Check equipment settings when comparing loads across machines.
- For unilateral exercises, retain repetitions per side and left/right feedback. Completing both sides can count as one set under the user's existing convention, with the actual counting method explained separately.
- Preserve reported RIR ranges and plus signs. Record general warm-up, stretching, and changes in symptoms separately. Fill in completion of planned items from what was actually reported.
- Identify set rows by their parent event and a stable row number. Retain the basis for revisions when correcting a row's load, repetitions, or feedback. Update the parent summary to reflect the current set count and whether the session has ended.

## Running and Climbing

| Area | Recording and review points |
| --- | --- |
| Running totals | Save distance, timer time, and elapsed start-to-finish time separately. Retain the device's original seconds. If the interface only stores minutes, preserve precise start and end times in the body. State which distance and duration were used for average pace. |
| Running details | Record distance, timing, targets, actual performance, and recovery segments for splits or intervals. Explain differences in totals caused by display rounding. Analyze whole-session average pace and fast-interval pace separately. |
| Running sources | When screenshots and the original Workout differ in distance, energy expenditure, or heart rate, retain both sources and explain the value chosen for the main field. Specify whether heart rate covers the full session, a sleep window, or a defined aggregation window, and whether cadence includes walking recoveries. Fill in route, elevation gain, shoes, and running dynamics from actual evidence. |
| Climbing | Distinguish bouldering, roped climbing, and other types. Record the venue, grading system, route or problem, attempt count, completion style, and subjective feedback. Compare coverage between short device-recorded segments and a manually reported full session before deciding whether to combine them or retain them separately. |

Match a workout to its plan using the user's identification, a workout identifier, or its date, activity type, and content. Similar distance alone makes it a candidate. Link the plan once the match is confirmed. Judge whether individual workout segments met their targets from actual splits or the user's report. Keep a workout crossing midnight as one parent event. When sleep days are used, assign it by its actual start time and include the report time for later recovery feedback.

## Recipes and Actual Intake

- Recipe or product records store ingredients per serving, amounts, nutrition sources, and versions. Intake records store the version actually used, servings consumed, ingredient additions or omissions, and whether weights are raw or cooked. Product labels and recipe records serve as reference material.
- When the user changes a default recipe, record the evidence establishing when the change takes effect. Historical intake keeps the recipe actually used at the time. For a correction to a historical fact, update the corresponding original record and retain the reason.
- Record planned, consumed, partially consumed, and cancelled intake separately. State assumptions for photo-based portions, shared food, and leftovers. When a portion cannot be determined, retain an estimated range or an item to verify.
- Count supplement doses, caffeinated products, and ingredients in drink combinations according to the servings actually consumed. If an ingredient is already included in a combination, check whether there was another actual serving.
- Explain the coverage, estimates, and missing values in nutrition totals. Report a provisional subtotal for known components where appropriate. Leave unavailable macronutrient or calorie values blank.

## Body Measurements and DEXA

- Use one parent event per measurement session. Preserve each original reading, its unit, measurement site, and the method used to derive a representative value. If only a representative value is available, identify that source format.
- Use the units and frequency in the user's protocol for body weight, circumferences, and skinfolds. Treat same-day averages and trends across days as analysis, with references to the original sessions.
- Store the DEXA report's actual fields separately, including body-fat percentage, fat mass, lean tissue, bone mineral measurements, and regional metrics. Record the device, measurement time, food intake, hydration, bladder emptying, and recent exercise conditions.
- Keep skinfold estimates and DEXA results within their respective methods and trends. Mark the conditions for a new baseline when the measurement protocol changes. Consider hydration and measurement error when interpreting changes in lean tissue.

## Later Additions and Cross-Domain Review

Write later additions back to the corresponding original event, then check the current fields and summaries directly affected. For example, once gel consumption during a run has been confirmed in the food module, reference that original intake record from the training page and update any current description that still says fueling is unknown. Nutrition totals come from the original intake record. The training page retains the link and explanation.

After a sleep day boundary (the final wake-up from main sleep), event start or end time, or counting flag is revised, recheck affected parent events, child details, and summaries. Use revised boundaries in the current assignment evidence and mark old evidence as historical. Preserve original evidence and dated interim snapshots, while showing the latest verified status at the current entry point.

## Plan Versions and Execution Progress

For a new project, draft an achievable training week using recent completed training volume and intensity, the target date, available weekly time slots and equipment, and feedback on sleep, fatigue, and discomfort. Specify each session's purpose, expected duration, sets or running distance, intensity range, and recovery arrangements, accounting for the combined load across activities. If training history is missing, state the starting assumptions and choose an adjustable initial volume. Revise it using actual completion and recovery feedback. Save the draft's rationale and items awaiting confirmation, then update the active version after the user adopts it.

- Save statuses such as draft, confirmed, superseded, and ended, along with confirmation evidence, effective scope, and the previous version. State the scope when the user adopts only part of a recommendation.
- Preserve the intended plan dates, expected sets, target distances, and paces. Link actual execution through original training events, and explain cancellations, partial completion, additional work, and rescheduling separately.
- When a confirmed schedule has actual execution records, update its current progress summary or add a dated execution section with links to the original events. Label the original schedule snapshot with its point in time.
- For a run on the planned day with matching distance but missing splits, a suitable description is "Corresponding run recorded; workout segments await verification." For a one-session exercise substitution or reduction in strength sets, record the change and reason for that session. Revise the long-term template separately according to what the user adopts.
- When reporting progress, check both the latest active plan version and the original events. Keep goals, intake targets, or recovery arrangements that are still recommendations marked as recommendations.

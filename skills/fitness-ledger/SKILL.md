# Fitness Ledger · 运动计划与记录

[简体中文](#中文) · [English](#english)

Use the user’s language for replies and new text. Preserve existing Notion page titles, property names, options, and units in their original language. Choose the reference in the language you need.

按用户使用的语言回复和撰写新内容。既有 Notion 页面标题、字段名、选项和单位沿用原文。

## 中文

从用户指定的项目入口读取最新协作规范，找到该专项的原始数据库、填写模板和维护日志。把稳定的记录方法放在 Skill，把个人目标、当前计划、时区、产品份量和页面映射保存在用户自己的项目内。以当前能访问的原始证据为依据。

通过当前环境已授权的 Notion 连接读取项目主页或索引，依据真实页面标题和目标库字段确认工作位置。首次验证可只读返回主页标题和有关库的位置。另按目标库权限判断能否写入。

**首次接手**时，先用当前聊天已提供的入口和时区。如果没有入口，仍可根据用户输入整理一份待保存记录，只在需要绑定目标库时询问入口。若用户要求从空白页建账，按下表从当前要用的模块开始，在索引里登记真实页面、数据源和负责人。已有项目先复用原库。

| 模块 | 保存的内容 |
| --- | --- |
| 项目看板 | 各业务库的视图、计划进度和需复核事项 |
| 每日汇总 | 作息周期、开日睡眠、午间及最终摘要、旧归档对照 |
| 饮食与补剂 | 实际摄入、食物规则、产品标签和份量版本 |
| 运动训练 | 一场一次的训练原记录，力量逐组或其他从属明细 |
| 身体数据 | 一次测量会话及其逐项读数 |
| 目标与计划 | 本人目标、备选方案、已采纳的计划版本和对应执行记录 |
| 项目管理 | 索引、协作规范、记录模板、维护日志 |

按这次任务选读以下资料。

- 编排训练、登记实际事件或处理补报时，使用[专项记录与计划](references/event-records.md)。
- 判断凌晨事件归属、读取 Apple Health 睡眠或执行每日运动双汇总时，使用[作息日与双汇总](references/sleep-day.md)。由双汇总维护共享周期，训练、饮食、体测聊天引用同一个周期。
- 做周检、整理视图和修订记录规则时，使用[每周维护](references/weekly-review.md)。

**写入时**，先按来源事件 ID 查重。没有 ID 时，核对本人、项目、当地发生时间与时区、数量或设备。保留同日多次真实事件。区分发生时刻、旧归档标签、录入时刻和最后修改时刻。能定位周期时只关联一个，并写明已核验或推定及其依据。归属不清时保留原事件，周期留空并标为待核对。计划、实际发生、主观反馈和分析在记录中分别标注。未知数值留空。

在用户已授权的目标内做局部更新，保留原始值、出处、估计方法及更正原因。写后回读页面、关系和受影响的摘要。创建结果不明时先查重。若缺少相应连接或写权限，交付可直接录入的内容，说明哪些来源读到了、哪些字段待核、哪些写入已成功。

**接续聊天时**，从索引、当前已确认的计划、最近一个有关原事件及未决事项恢复工作。交接时给出这些页面的私有链接和下一次应核对的证据。用户要求的周检或双汇总频率与实际定时任务设置分开管理。

## English

Read the current collaboration rules from the user's project home or index through the Notion connection available in this chat. Identify the source database for the task, its template and the maintenance log. Use the page titles and database properties actually returned. For a read-only connection check, report the project title and location of the relevant databases. Assess edit access separately for the target database. Keep personal goals, confirmed plans, time zone, serving sizes and page mappings in the user's project. Base each entry on sources you can actually access.

**When taking over a project**, reuse the project link and time zone already supplied. If the link is missing, you can prepare an entry from the user's report and ask for the destination when ready to save. If the user requests a new ledger in an empty page, start with the modules needed for the task and register their actual pages, data sources and owners in the index. Reuse the original databases in an existing project.

| Module | What it holds |
| --- | --- |
| Dashboard | Views of source databases, plan progress and items needing review |
| Daily summaries | Sleep days, the main sleep that opened each day, midday and final summaries, and legacy totals for comparison |
| Food and supplements | Actual intake, food rules, product labels and versions of serving sizes |
| Training | One source record per workout, with strength sets or other details attached |
| Body measurements | One source record per measurement session and its individual readings |
| Goals and plans | Personal goals, proposals, adopted plan versions and links to actual sessions |
| Project management | Index, collaboration rules, entry templates and maintenance log |

Read the reference relevant to the request.

- For training plans, actual events and late reports, use [Event records and plan progress](references/event-records.en.md).
- For overnight events, Apple Health sleep samples and daily summaries, use [Sleep days and daily summaries](references/sleep-day.en.md). The daily-summary workflow maintains the shared sleep days. Training, nutrition and measurement chats use those same records.
- For the weekly audit, navigation and changes to recording rules, use [Weekly review](references/weekly-review.en.md).

**When recording an event**, look for its source event ID first. If none is available, check the person, activity, local occurrence time and time zone, amount or device. Preserve separate sessions that happened on the same day. Track the occurrence time, legacy filing date, entry time and last edit separately. Link an event to at most one sleep day and mark the assignment as verified or estimated, with its basis. When its sleep day is unclear, retain the event, leave the relation empty and mark it for review. Label plans, actual events, personal feedback and analysis separately. Leave unknown quantities blank.

Make local edits within the scope authorized by the user. Preserve original values, sources, estimation methods and reasons for corrections. Read back the page, its relations and affected summaries after writing. If creation returns an uncertain result, look for the original before retrying. When the connection or write access is missing, provide the prepared entry and identify which sources were read, which fields need review and which changes were saved.

**When handing off to a new chat**, use the index, the latest confirmed plan, the most recent relevant source event and open questions to resume work. Supply private links in the user's own chat and identify the next evidence to check. Track the requested reporting cadence separately from any scheduler configuration.
